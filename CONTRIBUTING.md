# Contributing

Thank you for your interest in contributing to Blackboard.

Every contribution helps improve the project.

---

## Development Workflow

1. Fork the repository.

2. Create a feature branch.

```
feature/my-awesome-feature
```

3. Commit your work.

4. Push to your fork.

5. Open a Pull Request.

---

## Branches

main

Stable production releases only.

dev

Current development branch.

feature/*

New features.

fix/*

Bug fixes.

docs/*

Documentation updates.

---

## Pull Requests

Before opening a Pull Request

- Build successfully
- Test your changes
- Keep commits focused
- Follow project style

Large features should first be discussed in an Issue.

---

## Coding Style

Keep code

- Readable
- Modular
- Consistent
- Documented where necessary

Avoid unnecessary dependencies.

---

## Issue Reporting

When reporting bugs include

- Operating System
- Blackboard Version
- Steps to reproduce
- Expected behaviour
- Actual behaviour

Screenshots are appreciated.

---

## Feature Requests

Please explain

- Why it is useful
- Existing workflow
- Proposed solution

---

## Code Ownership

Maintainers reserve the right to reject Pull Requests that do not align with the project's goals.

This helps maintain a consistent direction.

---

Thank you for helping improve Blackboard.
